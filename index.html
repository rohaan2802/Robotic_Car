Overview

Robotic Car is a NodeMCU-powered teleoperation and occupancy-mapping prototype. A phone or laptop connects to the car’s ESP8266 access point. The firmware controls the L298N motor driver and exposes ultrasonic range and MPU6050 orientation over HTTP. The Python tools inspect the saved map, demonstrate the mapping algorithm offline, and query or send short drive pulses to the board.

Project Breakdown

SubsystemInputOutput
Drive controlF, B, L, R, RL, RR, SESP8266 translates commands into L298N pin states and caps requested motion at 1 second.
RangeForward ultrasonic echoMeasured centimeters or −1 when no echo arrives.
OrientationMPU6050 DMP packetYaw, pitch and roll in degrees. Missing or stale samples return HTTP 503.
MappingPose (x, y, heading) and a range ≤100 cmMark preceding cells free and the measured cell occupied with bounded Bayesian evidence.
ReviewSaved .npy grid or eight synthetic observationsInspectable map plot with classified cell counts.

Valid range data updates only the cells preceding the hit and the endpoint itself. The firmware checks the requested duration and stops motor output when a pulse expires.

Results

The original 500 × 500 snapshot contains 1,195 free, 248,801 unknown, and 4 occupied cells at the documented thresholds. The sparse rays are evidence from the saved grid. The synthetic demo runs eight labeled range observations from two poses to exercise the same mapping code without hardware.

The recording and saved grid come from the original project. The synthetic plot and regression checks are reproducible offline.

Setup

Run these PowerShell commands from the project directory to inspect the map and rerun the tests.

python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe -m robotic_car review
.venv\Scripts\python.exe -m robotic_car demo

For the board, see wiring, flashing and endpoint details. Use python -m robotic_car scan --help to add a live range observation at a manually specified pose.

Limitations

The MPU6050 yaw can drift. A single forward ultrasonic sensor samples a narrow region, and the map assumes that pose is supplied and calibrated. The grid does not recover position, fuse scans from multiple cars, or perform autonomous planning. The course report describes a multi-robot design, while the maintained code controls one car over HTTP.
